PRODUCTION STEPS
1. Recover and inspect the original production kit, first cut, brand kit and rights.
2. Export the three briefs:
   node --experimental-strip-types scripts/dusk/export-briefs.ts work/dusk-briefs
   All variants use the same BODY and body_sha256. Hook h1 = molecular curiosity;
   h2 = evidence literacy; h3 = compound introduction. CTA and shared body stay fixed.
3. In the admin dashboard, read the hook, shared body and primary paper; mark each
   script reviewed. Agent output is a draft, never an approval.
4. Use a licensed narration voice and locked transcript. Render one shared body
   master. Make three short hook clips. Keep disclaimers readable, captions clear,
   and text inside platform safe areas. Source timings are editorial targets,
   not verified voice timings. Create final SRT from locked audio, not estimates.
5. Runway is technically suitable for licensed source-image motion/backgrounds.
   Official API: https://docs.dev.runwayml.com/api/
   Getting started: https://docs.dev.runwayml.com/guides/using-the-api/
   API access requires Runway Dev credentials/credits; none available here.
   Preserve exact labels via editor compositing; generated labels are unreliable.
   No provider-specific API integration or paid generation was executed.
6. Local assembly (requires ffmpeg, or DUSK_FFMPEG pointing to its executable):
   node scripts/dusk/assemble.mjs hook-h1.mp4 shared-body.mp4 h1.mp4
   Repeat for h2/h3 using the exact same shared-body.mp4. Inputs must have audio.
   The helper normalizes to 1080x1920 / 30fps / H.264 + AAC and writes a provenance
   sidecar with hook, shared-body and final-cut SHA-256 values. It never overwrites
   an existing MP4 or grants approval. Cropping, duration and audio need human QA.
7. Archive the final files at dusk/pinealon/<name>.mp4 in your controlled asset
   archive. The app stores relative archive references, not uploaded files or URLs.
   Calculate the brand-kit and MP4 SHA-256 checksums. Review the actual playback,
   narration, captions, rights and research framing. Record render metadata in the
   dashboard; approve only that exact cut. An attestation is not automated file QA.
8. Any change to the cut or scientific script requires returning to draft and
   another review. The current script version is fixed: pinealon-research-v1.
9. Manual publication: use the per-channel link from each JSON brief. Platform
   eligibility and advertising review remain unverified. No posts or ads sent.
10. Review consent-based reported landings and study clicks. Keep channel, spend,
    impressions and verified purchases in their authoritative systems; this MVP
    neither imports ad performance nor attributes revenue, and selects no winner.
